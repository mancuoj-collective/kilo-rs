第 5 课 · 光标与滚动

kilo-rs 课程 · Lesson 0005 · 预计 35–45 分钟 · 加功能 + 第一次写测试

文件能显示了，但你只能看第一屏，而且没有光标。
这一课让光标动起来、让画面跟着它滚动——同时第一次把「一堆相关状态」收进一个结构 Editor，并为它写单元测试。还记得第 4 课为什么拆 lib.rs 吗？回报来了。

本课成果

  • 方向键移动光标，画面自动滚动跟随；
  • Home/End 跳到行首 / 行尾；
  • 光标落在屏幕上的正确位置（终端光标可见）；
  • 新增 src/editor.rs 和 3 个单元测试——不启动终端就能验证逻辑。

核心概念：文件坐标 vs 屏幕坐标

文件可能比屏幕大，所以「光标在哪」和「光标画在哪」是两件事，中间隔着一个视口：

量含义
cx / cy光标在文件里的位置（列、行）。
rowoff / coloff视口左上角对应文件的哪一行、哪一列。
屏幕位置cy - rowoff 行、cx - coloff 列。

每次按键后调用一次 scroll，保证光标落在可视范围内；渲染时用视口偏移去取内容。

一个细节 上下移动时，如果新行更短，列要夹回行尾。 比如在第 5 列按 ↓ 落到一条只有 3 个字符的行，光标应停在列 3。原版 kilo 就是这么做的。

scroll 的公式怎么来的 视口在文件里覆盖 [rowoff, rowoff + rows)。

  • 光标跑到视口上方（cy < rowoff）→ 让视口顶到光标：rowoff = cy（光标落在屏幕第 0 行，贴顶）。
  • 光标跑到视口下方（cy >= rowoff + rows）→ 让光标落在屏幕最后一行： rowoff = cy - rows + 1。+1 是因为窗口有 rows 格、最后一格编号是 rows - 1。

水平方向（cx/coloff/cols）同理。跑完后必有 rowoff <= cy < rowoff + rows 与 coloff <= cx < coloff + cols， 所以 cy - rowoff、cx - coloff 一定落在屏幕内——这就是 draw 敢直接用它的原因。

为什么现在收进结构

上一课状态还是局部变量，现在一下多出 4 个（cx/cy/rowoff/coloff）， 而且它们总是一起被读写——这就是「接缝清晰了」。把它们装进 Editor， 行为（移动、滚动）也归它。关键点：Editor 完全不碰终端。

此刻兑现 因为 Editor 不知道终端的存在，它可以直接被单元测试： 给定一串操作，断言光标/视口。这正是「把逻辑放进库」换来的东西——不启动界面也能测核心逻辑。

动手

任务 1 新建 src/editor.rs

//! Editable editor state: cursor position and viewport scrolling.
//!
//! This layer never touches the terminal: it only tracks where the cursor is and which
//! row/column the screen starts at. Because it doesn't depend on the terminal, it can be
//! unit-tested directly — the payoff of putting logic in a library.

/// A cursor movement direction.
#[derive(Clone, Copy)]
pub enum Move {
    Left,
    Right,
    Up,
    Down,
    Home,
    End,
}

/// Editor state: buffer contents, cursor, and viewport.
pub struct Editor {
    lines: Vec<String>,
    /// Cursor position in chars: `cx` is the column, `cy` the row.
    cx: usize,
    cy: usize,
    /// Top-left of the viewport, as `(column, row)` in the file.
    coloff: usize,
    rowoff: usize,
}

impl Editor {
    /// Creates a new editor from the given lines; cursor and viewport start at the top-left.
    #[must_use]
    pub fn new(lines: Vec<String>) -> Self {
        Self {
            lines,
            cx: 0,
            cy: 0,
            coloff: 0,
            rowoff: 0,
        }
    }

    /// Buffer contents, for rendering.
    #[must_use]
    pub fn lines(&self) -> &[String] {
        &self.lines
    }

    /// Cursor position in the file, as `(column, row)`.
    #[must_use]
    pub fn cursor(&self) -> (usize, usize) {
        (self.cx, self.cy)
    }

    /// Top-left of the viewport in the file, as `(column, row)`.
    #[must_use]
    pub fn viewport(&self) -> (usize, usize) {
        (self.coloff, self.rowoff)
    }

    /// Moves the cursor in the given direction.
    pub fn move_cursor(&mut self, direction: Move) {
        let numrows = self.lines.len();
        match direction {
            Move::Left => {
                if self.cx > 0 {
                    self.cx -= 1;
                } else if self.cy > 0 {
                    self.cy -= 1;
                    self.cx = self.current_line_len();
                }
            }
            Move::Right => {
                if self.cy < numrows {
                    if self.cx < self.current_line_len() {
                        self.cx += 1;
                    } else {
                        self.cy += 1;
                        self.cx = 0;
                    }
                }
            }
            Move::Up => {
                if self.cy > 0 {
                    self.cy -= 1;
                }
            }
            Move::Down => {
                if self.cy < numrows {
                    self.cy += 1;
                }
            }
            Move::Home => self.cx = 0,
            Move::End => self.cx = self.current_line_len(),
        }

        // Moving to a shorter line: clamp the column to the line end.
        self.cx = self.cx.min(self.current_line_len());
    }

    /// Adjusts the viewport so the cursor stays visible.
    pub fn scroll(&mut self, rows: usize, cols: usize) {
        if self.cy < self.rowoff {
            self.rowoff = self.cy;
        }
        if self.cy >= self.rowoff + rows {
            self.rowoff = self.cy - rows + 1;
        }
        if self.cx < self.coloff {
            self.coloff = self.cx;
        }
        if self.cx >= self.coloff + cols {
            self.coloff = self.cx - cols + 1;
        }
    }

    /// Number of chars in row `cy`; 0 if the row doesn't exist.
    fn line_len(&self, cy: usize) -> usize {
        self.lines.get(cy).map_or(0, |line| line.chars().count())
    }

    /// Number of chars in the cursor's row (0 on the empty line past EOF).
    fn current_line_len(&self) -> usize {
        self.line_len(self.cy)
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    fn editor() -> Editor {
        Editor::new(vec![String::from("hello"), String::from("world!!")])
    }

    #[test]
    fn right_moves_within_a_line() {
        let mut e = editor();
        e.move_cursor(Move::Right);
        assert_eq!(e.cursor(), (1, 0));
    }

    #[test]
    fn moving_up_clamps_column_to_line_end() {
        let mut e = editor();
        e.move_cursor(Move::End); // end of the first line: column 5
        e.move_cursor(Move::Down);
        assert_eq!(e.cursor(), (5, 1));
        e.move_cursor(Move::Up);
        assert_eq!(e.cursor(), (5, 0));
    }

    #[test]
    fn scroll_keeps_cursor_visible() {
        let mut e = Editor::new((0..10).map(|i| format!("line {i}")).collect());
        e.move_cursor(Move::Down);
        e.move_cursor(Move::Down);
        e.move_cursor(Move::Down); // cy = 3
        e.scroll(3, 20); // viewport is only 3 rows tall
        assert_eq!(e.viewport(), (0, 1)); // rowoff = 3 - 3 + 1
    }
}

任务 2 更新 src/lib.rs

声明 editor 模块，用 Editor 驱动事件循环，渲染时按视口偏移取内容：

//! kilo-rs: a text editor rewritten from kilo in Rust.
//!
//! Logic lives in the library (so integration tests can reach it); `main.rs` is a thin
//! shell. Terminal lifecycle is in [`tui`], editor state in [`editor`]; rendering and the
//! event loop stay here for now, to split into `ui` / `app` later.

pub mod editor;
pub mod tui;

use std::{
    env, fs,
    io::{self, Write},
};

use color_eyre::Result;
use crossterm::{
    cursor::{self, MoveTo},
    event::{self, Event, KeyCode, KeyModifiers},
    queue,
    style::Print,
    terminal::{self, Clear, ClearType},
};

use crate::{
    editor::{Editor, Move},
    tui::Terminal,
};

const NAME: &str = env!("CARGO_PKG_NAME");
const VERSION: &str = env!("CARGO_PKG_VERSION");

/// Runs the editor: read the file, take over the terminal, enter the event loop.
///
/// # Errors
///
/// Returns an error if reading the file or a terminal operation fails.
pub fn run() -> Result<()> {
    // Read the file name from argv; with no argument, start with an empty buffer.
    let lines = match env::args().nth(1) {
        Some(path) => fs::read_to_string(&path)?
            .lines()
            .map(str::to_owned)
            .collect(),
        None => Vec::new(),
    };

    let mut editor = Editor::new(lines);

    let _guard = Terminal::enter()?;
    draw(&mut editor)?;

    loop {
        match event::read()? {
            Event::Key(key) if key.is_press() => match key.code {
                KeyCode::Char('q') if key.modifiers.contains(KeyModifiers::CONTROL) => break,
                KeyCode::Up => editor.move_cursor(Move::Up),
                KeyCode::Down => editor.move_cursor(Move::Down),
                KeyCode::Left => editor.move_cursor(Move::Left),
                KeyCode::Right => editor.move_cursor(Move::Right),
                KeyCode::Home => editor.move_cursor(Move::Home),
                KeyCode::End => editor.move_cursor(Move::End),
                _ => {}
            },
            _ => {}
        }
        draw(&mut editor)?;
    }

    Ok(())
}

/// Draws one frame: render the file at the viewport offset, then place the terminal
/// cursor at the editor cursor.
///
/// Calls [`Editor::scroll`] first, hence the `&mut Editor`.
fn draw(editor: &mut Editor) -> io::Result<()> {
    let (cols, rows) = terminal::size()?;
    let width = cols as usize;
    let height = rows as usize;

    editor.scroll(height, width);

    let (coloff, rowoff) = editor.viewport();
    let (cx, cy) = editor.cursor();
    let lines = editor.lines();

    let mut stdout = io::stdout();
    queue!(stdout, cursor::Hide, Clear(ClearType::All), MoveTo(0, 0))?;

    for y in 0..height {
        let filerow = rowoff + y;
        if let Some(line) = lines.get(filerow) {
            let text: String = line.chars().skip(coloff).take(width).collect();
            queue!(stdout, Print(text))?;
        } else if lines.is_empty() && y == height / 3 {
            queue!(stdout, Print(welcome_line(cols)))?;
        } else {
            queue!(stdout, Print('~'))?;
        }

        if y + 1 < height {
            queue!(stdout, Print("\r\n"))?;
        }
    }

    // The viewport guarantees the cursor is on screen, so these conversions can't fail.
    let cursor_col = u16::try_from(cx - coloff).expect("cursor column should be inside the viewport");
    let cursor_row = u16::try_from(cy - rowoff).expect("cursor row should be inside the viewport");
    queue!(stdout, MoveTo(cursor_col, cursor_row), cursor::Show)?;
    stdout.flush()
}

/// Truncates text to the terminal width (by chars, not bytes).
fn truncate(text: &str, width: u16) -> String {
    text.chars().take(width as usize).collect()
}

fn welcome_line(cols: u16) -> String {
    let text = format!("~ {NAME} editor -- version {VERSION}");
    truncate(&text, cols)
}

逐段拆解

  • Editor 不 import 任何 crossterm：这是有意的。它只管状态， 「按键怎么映射到移动」由 lib.rs 的事件循环负责。于是 Editor 可测、可复用、 以后换 TUI 库也不受影响。
  • Move 派生 Copy：它是个小的「标签」枚举，按值传递最自然。 不派生 Copy 的话，clippy::pedantic 会提示「按值传入但没消费」，让你改成引用—— 一个不该按引用传的值类型反而被建议传引用，就是这个 lint 在提醒你补 Copy。
  • getter 上的 #[must_use]：clippy::pedantic 要求公开的「返回值的函数」标注 #[must_use]——因为忽略 cursor() 的返回值多半是写错了。
  • line_len 用 chars().count() 而不是 len()： cx 是字符列，不是字节列。这跟第 2 课 truncate 是同一件事。
  • Move::Right 在行尾时跳到下一行行首：这是编辑器的常见行为，也让「按右箭头穿过整个文件」成立。
  • scroll 的四条 if：把光标夹进 [rowoff, rowoff + rows) 与 [coloff, coloff + cols)。之后 cursor_col = cx - coloff 必然落在屏幕内， 所以那句 try_from 不会失败——用 unwrap_or 是为了不 panic，也不需要 unsafe 假设。
  • draw 需要 &mut Editor，因为它顺手调用了 scroll（调整视口属于「渲染前的一次状态更新」）。 以后拆 ui.rs 时，我们会把「滚动」和「纯渲染」分得更干净。

事件循环的形状 每轮固定是：读事件 → 按事件改状态 → 无条件重画一帧。 「确定视口」就是 draw 开头的 editor.scroll(...)。

  • 两个 _ => {} 各管一层：内层忽略还没处理的按键（如字母）， 外层忽略非按键事件（Resize、鼠标…）。
  • break 直接跳出 loop，跳过本轮的 draw——要退出了，没必要再画。
  • Resize 虽被忽略，但 draw 在 match 之后无条件执行，所以它照样会按新尺寸重画。 这就是窗口变化能自适应的原因。

小测

1. 光标画在屏幕第几行，由什么决定？

  • cy - rowoff
  • cy + rowoff
  • cy 本身
  • rowoff - cy
看答案

第一个。视口左上角对应文件的第 rowoff 行，所以文件第 cy 行在屏幕上是第 cy - rowoff 行。

2. Editor 为什么不 import crossterm？

  • 为了让它能脱离终端被测试
  • 因为 crossterm 不允许被库引用
  • 因为 Move 枚举无法携带 crossterm 类型
  • 为了减小编译出来的二进制体积
看答案

第一个。状态层不依赖终端，就能在普通测试里「喂操作、断言状态」， 不需要 pty、不需要真实屏幕。这就是深模块 + 可测试的核心价值。

3. 在一条长行的第 8 列按 ↓ 到一条只有 5 个字符的行，光标会到哪？

  • 列 5，被夹回行尾
  • 列 8，保持不变
  • 列 0，回到行首
  • 列 5 然后自动换到下一行
看答案

第一个。移动结束后统一做 cx.min(current_line_len())， 把列夹进当前行的范围。这是「光标不能超过行尾」这条不变式的落点。
