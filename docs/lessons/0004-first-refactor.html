第 4 课 · 第一次重构

这一课一个新功能都不加。我们要把已经写出来的东西重新摆放： 终端生命周期搬进 src/tui.rs，逻辑搬进 src/lib.rs， src/main.rs 只剩一层薄外壳。这是本课程「拆模块」目标的第一次落地。

本课成果

  • 一个 lib.rs + tui.rs + 薄 main.rs 的三文件结构；
  • tui 成为第一个深模块：对外只暴露两个入口，内部藏着全部终端恢复逻辑；
  • 行为和上一课一模一样（打开文件、重画、Ctrl-Q 退出、panic 干净恢复）；
  • 从此以后，逻辑可以被 tests/ 里的集成测试 use kilo::… 直接测试。

为什么是现在

重构的时机不是「文件太长」，而是「接缝清晰了」。终端生命周期恰好是最干净的一刀：

  • 概念单一：raw mode、备用屏幕、光标必须成对开关，它们其实是同一个概念。
  • 接口极小：对外只需要「进入」和「装 panic hook」两个入口。
  • 零耦合：它完全不知道「编辑器」「文件」「光标」是什么。

铁律：行为不变的搬家

  1. 先让现有功能跑通（编译 + 运行 + clippy 都过）。
  2. 只做搬家，一行逻辑都不改。
  3. 再跑一遍，确认行为一模一样。

绝不「一边重构一边加功能」——否则「搬家搬错了」和「新功能有 bug」会混在一起，没法定位。

目标结构

src/
├── main.rs   # 薄外壳：color-eyre + 装 hook + 调用库
├── lib.rs    # 逻辑入口：run()、draw()、truncate()…
└── tui.rs    # 终端生命周期：Terminal 守卫 + panic hook

动手

任务 1 新建 src/tui.rs

把 Terminal、restore、install_panic_hook 原样搬到这里：

//! Terminal lifecycle management.
//!
//! Wraps the must-be-paired operations (raw mode, alternate screen, cursor) in a
//! [`Terminal`] guard, and restores the terminal on panic via [`install_panic_hook`].

use std::io;

use crossterm::{
    cursor,
    execute,
    terminal::{self, EnterAlternateScreen, LeaveAlternateScreen},
};

/// Guard for full-screen editing state.
///
/// While held, the terminal is in raw mode, on the alternate screen, with the cursor
/// hidden; dropping it restores the terminal — on a normal return, an early `?`
/// return, or a panic unwind.
pub struct Terminal;

impl Terminal {
    /// Enters full-screen editing state.
    ///
    /// # Errors
    ///
    /// Returns the underlying [`io::Error`] if the terminal is unavailable.
    pub fn enter() -> io::Result<Self> {
        terminal::enable_raw_mode()?;

        // Build the guard first; if the command below fails, `guard` drops and raw
        // mode is restored.
        let guard = Self;
        let mut stdout = io::stdout();
        execute!(stdout, EnterAlternateScreen, cursor::Hide)?;

        Ok(guard)
    }
}

impl Drop for Terminal {
    fn drop(&mut self) {
        restore();
    }
}

/// Installs a panic hook that restores the terminal, then hands off to the
/// previous hook.
///
/// Must be called *after* other hooks (e.g. `color_eyre::install`) are set.
pub fn install_panic_hook() {
    let hook = std::panic::take_hook();
    std::panic::set_hook(Box::new(move |info| {
        restore();
        hook(info);
    }));
}

/// Restores the terminal. Shared by `Drop` and the panic hook.
fn restore() {
    let mut stdout = io::stdout();
    let _ = execute!(stdout, cursor::Show, LeaveAlternateScreen);
    let _ = terminal::disable_raw_mode();
}

任务 2 新建 src/lib.rs

把 main 里的逻辑（读文件、事件循环、渲染）搬过来，改名为 run， 并声明 tui 模块：

//! kilo-rs: a text editor rewritten from kilo in Rust.
//!
//! Logic lives in the library (so integration tests can reach it); `main.rs` is a thin
//! shell. Only the terminal lifecycle is split into [`tui`] so far; as it grows, `run`
//! / `draw` here will split into `app`, `ui`, `document`, `row`, `syntax`.

pub mod tui;

use std::{
    env, fs,
    io::{self, Write},
};

use color_eyre::Result;
use crossterm::{
    cursor::MoveTo,
    event::{self, Event, KeyCode, KeyModifiers},
    queue,
    style::Print,
    terminal::{self, Clear, ClearType},
};

use crate::tui::Terminal;

const NAME: &str = env!("CARGO_PKG_NAME");
const VERSION: &str = env!("CARGO_PKG_VERSION");

/// Runs the editor: read the file, take over the terminal, enter the event loop.
///
/// # Errors
///
/// Returns an error if reading the file or a terminal operation fails.
pub fn run() -> Result<()> {
    // Read the file name from argv; with no argument, start with an empty buffer.
    let lines = match env::args().nth(1) {
        Some(path) => fs::read_to_string(&path)?
            .lines()
            .map(str::to_owned)
            .collect(),
        None => Vec::new(),
    };

    let _guard = Terminal::enter()?;
    draw(&lines)?;

    loop {
        match event::read()? {
            Event::Key(key) if key.is_press() => match key.code {
                KeyCode::Char('q') if key.modifiers.contains(KeyModifiers::CONTROL) => break,
                _ => {}
            },
            Event::Resize(_, _) => draw(&lines)?,
            _ => {}
        }
    }

    Ok(())
}

/// Draws one frame: the first lines of the file, padded with `~`; the welcome
/// line for an empty file.
fn draw(lines: &[String]) -> io::Result<()> {
    let (cols, rows) = terminal::size()?;
    let mut stdout = io::stdout();

    queue!(stdout, Clear(ClearType::All), MoveTo(0, 0))?;

    for y in 0..rows {
        if let Some(line) = lines.get(y as usize) {
            queue!(stdout, Print(truncate(line, cols)))?;
        } else if lines.is_empty() && y == rows / 3 {
            queue!(stdout, Print(welcome_line(cols)))?;
        } else {
            queue!(stdout, Print('~'))?;
        }

        if y + 1 < rows {
            queue!(stdout, Print("\r\n"))?;
        }
    }

    queue!(stdout, MoveTo(0, 0))?;
    stdout.flush()
}

/// Truncates text to the terminal width (by chars, not bytes).
fn truncate(text: &str, width: u16) -> String {
    text.chars().take(width as usize).collect()
}

fn welcome_line(cols: u16) -> String {
    let text = format!("~ {NAME} editor -- version {VERSION}");
    truncate(&text, cols)
}

任务 3 把 src/main.rs 削成薄外壳

只留初始化和调用：

//! `kilo` binary entry point: setup + call into the library; no business logic.

use color_eyre::Result;

fn main() -> Result<()> {
    color_eyre::install()?;
    // Must come after color_eyre::install() to wrap the panic hook it sets.
    kilo::tui::install_panic_hook();
    kilo::run()
}

任务 4 验证「行为不变」

cargo run -- kilo.c
cargo clippy --all-targets -- -D warnings

应该和上一课完全一样：文件铺满、空行 ~、Ctrl-Q 退出。 如果哪里不一样，就是搬家搬错了，退回去重搬。

逐段拆解

  • main.rs 现在只剩三行调用。它做的是「二进制该做的事」：初始化错误上报、 装 panic hook、调用库。业务逻辑一行都不在这里。
  • 为什么 color_eyre::install() 和 install_panic_hook() 都留在 main： 它俩有顺序依赖（hook 必须在 install 之后装）。把有顺序约束的两个调用放在一起， 约束就写在明面上，而不是拆散到两个文件里靠记忆维持。
  • kilo::tui::install_panic_hook() 里的 kilo：这是本包编译出的库 crate。 一个 package 可以同时有 lib.rs（库 kilo）和 main.rs（二进制 kilo）， 二进制依赖库，所以能用 kilo::…。
  • pub mod tui; / pub fn run() / pub struct Terminal： 二进制是另一个 crate，只能看到库的 pub 项。所以 main 用得到的东西必须是 pub。
  • fn restore() 保持私有：这是「深模块」的关键。对外只需要「进入」和「装 hook」， 恢复的细节属于内部不变式，不给外界滥用的机会。接口小，实现大——这就是深度。
  • use crate::tui::Terminal;：Rust 2018 起，路径用 crate:: 表示「本 crate 内部」。
  • //! 是模块/ crate 级文档，写在文件顶部；/// 是条目文档，贴在 fn/struct 上。 # Errors 段是因为本项目的 clippy::pedantic 要求公开的 Result 函数说明错误条件—— 写清楚对调用者是好事。

删除测试 假设删掉 tui.rs：raw mode、备用屏幕、光标、panic 恢复这四段逻辑 会重新散回 run 和 main 里，而且恢复的正确性不再有单一保证。 它通过了删除测试——它在挣饭吃。

下一步会拆什么

当功能长到接缝清晰时，按这个顺序继续（详见 参考 · 架构与文件结构）：

  1. 编辑功能到来 → document.rs + row.rs（缓冲区会形成深模块）。
  2. 光标与滚动 → editor.rs（cx/cy/rowoff/coloff 攒进一个结构）。
  3. 状态栏 → ui.rs（渲染抽成只读 &Editor 的函数）。
  4. 语法高亮 → syntax.rs。

小测

1. restore() 为什么保持私有？

  • 对外只需「进入」，恢复是内部不变式
  • 因为私有函数执行起来更快
  • 因为返回 () 的函数不能公开
  • 因为 Drop 只能调用私有函数
看答案

第一个。把恢复藏起来，外面就无法做出「只退出备用屏幕却不关 raw mode」这种半吊子操作， 接口因此变小、变安全。这正是深模块的意义。

2. 为什么把逻辑放进 lib.rs，而不是全留在 main.rs？

  • 集成测试能 use kilo::… 直接测逻辑
  • 库总是比二进制编译得更快一些
  • 二进制文件里不能写私有函数
  • lib.rs 会自动生成在线文档站
看答案

第一个。tests/ 目录里的集成测试只能链接库，链接不到二进制。 把逻辑放进库，才有了「不启动界面也能测核心逻辑」的可能。

3. main.rs 里的 kilo::run()，这个 kilo 指什么？

  • 本包编译出的那个库 crate
  • 操作系统里的进程名字
  • Cargo.toml 里的一行依赖项
  • 需要额外导入的第三方 crate
看答案

第一个。package 名是 kilo，它同时产出库 crate kilo 和二进制 crate kilo； 二进制 crate 依赖库 crate，所以 kilo::run() 调的是自己的库。
