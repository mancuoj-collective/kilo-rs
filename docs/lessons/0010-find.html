第 10 课 · 查找

kilo-rs 课程 · Lesson 0010 · 预计 50–60 分钟 · 加功能：实时查找与命中高亮

编辑器现在能打开、能编辑、能保存。但当一个文件有几百行，想找「那一处文字」时， 你只能靠肉眼扫。查找是编辑器的高频动作：按 Ctrl+F， 在消息栏输入关键字——边输边跳、命中处高亮； Enter 留下，Esc 还原。

本课成果

  • Ctrl+F 打开查找提示，每敲一个字符就重新定位到首个匹配并高亮；
  • ↓/→ 跳到下一个匹配，↑/← 跳到上一个，到末尾会环绕；
  • Enter 保留命中处的光标；Esc 还原到查找前的位置；
  • 查找结束自动清除高亮。整个查找只用了现成的消息栏提示，没有新窗口。

思路：命中高亮从哪来？

在原版 kilo 里，查找不只是「移动光标」，还要把命中的那几个字符反色显示。 这意味着渲染管线要能区分「普通文字」和「命中文字」。我们把这件事拆成两层：

谁知道「哪段命中」谁知道「命中长什么样」
Row它持有字符和命中的字符区间（match_range）不知道——只标记「这段是命中」
ui不知道它把命中段套上反显（Reverse）

于是 Row::render_window 不再返回一个 String，而是返回一串 Segment：文本 + 「是否命中」。谁也不想把终端的转义码写进 Row—— 那是渲染层的语言。

    /// Index of the first occurrence of `query` at or after char index `from`.
    #[must_use]
    pub fn find(&self, query: &str, from: usize) -> Option<usize> {
        let needle: Vec<char> = query.chars().collect();
        if needle.is_empty() || from > self.len() {
            return None;
        }

        let haystack = &self.chars[from..];
        if needle.len() > haystack.len() {
            return None;
        }

        (0..=haystack.len() - needle.len())
            .find(|&i| haystack[i..i + needle.len()] == needle[..])
            .map(|i| from + i)
    }

    /// Marks `range` (char indices) as the current search match; `None` clears it.
    pub fn set_match(&mut self, range: Option<Range<usize>>) {
        self.match_range = range;
    }

把 render_window 改成返回分段，并加一个小工具把相邻同类段并起来：

    /// Returns display columns `[coloff, coloff + width)`, split into highlighted and plain runs.
    #[must_use]
    pub fn render_window(&self, coloff: usize, width: usize) -> Vec<Segment> {
        let mut segments = Vec::new();
        let end = coloff + width;
        let mut col = 0;

        for (index, &ch) in self.chars.iter().enumerate() {
            let start = col;
            col = advance(col, ch);

            if col <= coloff {
                continue; // entirely left of the window
            }
            if start >= end {
                break; // window is full
            }

            let matched = self
                .match_range
                .as_ref()
                .is_some_and(|range| range.contains(&index));

            if ch == '\t' || start < coloff || col > end {
                // Expand tabs to spaces; pad a wide char straddling the edge with spaces.
                let from = start.max(coloff);
                let to = col.min(end);
                push_segment(&mut segments, &" ".repeat(to - from), matched);
            } else {
                let mut buf = [0u8; 4];
                push_segment(&mut segments, ch.encode_utf8(&mut buf), matched);
            }
        }

        segments
    }
}

/// Appends `text` to `segments`, merging it into the previous run when the match flag agrees.
fn push_segment(segments: &mut Vec<Segment>, text: &str, matched: bool) {
    if text.is_empty() {
        return;
    }
    match segments.last_mut() {
        Some(last) if last.matched == matched => last.text.push_str(text),
        _ => segments.push(Segment {
            text: text.to_owned(),
            matched,
        }),
    }
}

任务 3 改 src/editor.rs：查找状态与逻辑

先加三个类型：一个「怎么走」的枚举、一个不透明的「视口快照」，以及新增字段。

/// How [`Editor::find`] should step through matches.
#[derive(Clone, Copy)]
pub enum Find {
    /// The query changed: start again from the first row.
    FromStart,
    /// Move to the next match.
    Next,
    /// Move to the previous match.
    Prev,
}

/// A snapshot of the cursor and viewport; a cancelled search restores it.
#[derive(Clone, Copy)]
pub struct ViewState {
    cx: usize,
    cy: usize,
    coloff: usize,
    rowoff: usize,
}

在 Editor 的 message 字段后加一行，并在 new 里写 last_match: None：

    /// Captures the cursor and viewport; a cancelled search restores them.
    #[must_use]
    pub fn view_state(&self) -> ViewState {
        ViewState {
            cx: self.cx,
            cy: self.cy,
            coloff: self.coloff,
            rowoff: self.rowoff,
        }
    }

    /// Restores a snapshot taken by [`Editor::view_state`].
    pub fn restore_view(&mut self, view: ViewState) {
        self.cx = view.cx;
        self.cy = view.cy;
        self.coloff = view.coloff;
        self.rowoff = view.rowoff;
    }

    /// Removes the current search highlight.
    pub fn clear_matches(&mut self) {
        self.document.clear_matches();
    }

    /// Searches for `query`, moving the cursor to the match and wrapping around.
    pub fn find(&mut self, query: &str, how: Find) {
        self.document.clear_matches();
        if query.is_empty() {
            self.last_match = None;
            return;
        }

        let count = self.document.len();
        if count == 0 {
            self.last_match = None;
            return;
        }

        let start = match how {
            Find::FromStart => 0,
            Find::Next => self.last_match.map_or(0, |row| (row + 1) % count),
            Find::Prev => self
                .last_match
                .map_or(count - 1, |row| (row + count - 1) % count),
        };

        for offset in 0..count {
            let row = match how {
                Find::Prev => (start + count - offset) % count,
                Find::FromStart | Find::Next => (start + offset) % count,
            };
            if let Some(col) = self.document.row(row).and_then(|line| line.find(query, 0)) {
                self.last_match = Some(row);
                self.cx = col;
                self.cy = row;
                self.document
                    .set_match(row, col..col + query.chars().count());
                return;
            }
        }
        self.last_match = None;
    }

    #[test]
    fn find_moves_to_the_match_and_wraps() {
        let lines = [
            String::from("one"),
            String::from("two one"),
            String::from("three"),
        ];
        let mut e = Editor::new(&lines, None);

        e.find("one", Find::FromStart);
        assert_eq!(e.cursor(), (0, 0));
        e.find("one", Find::Next);
        assert_eq!(e.cursor(), (4, 1));
        e.find("one", Find::Next); // wraps back to the first row
        assert_eq!(e.cursor(), (0, 0));
        e.find("one", Find::Prev); // and backwards to the last match
        assert_eq!(e.cursor(), (4, 1));
    }

    #[test]
    fn restore_view_puts_the_cursor_back() {
        let mut e = editor();
        let saved = e.view_state();
        e.find("world", Find::FromStart);
        assert_eq!(e.cursor(), (0, 1));
        e.restore_view(saved);
        assert_eq!(e.cursor(), (0, 0));
    }

查找函数本身很短：拍下快照 → 让提示循环带回调 → 结束后清高亮，Esc 才还原：

/// Ctrl-F: live search; `Esc` restores the cursor, `Enter` keeps it.
fn find(editor: &mut Editor) -> io::Result<()> {
    let saved = editor.view_state();
    let query = prompt_with(editor, "Search: ", |editor, query, key| match key {
        KeyCode::Enter | KeyCode::Esc => {}
        KeyCode::Up | KeyCode::Left => editor.find(query, Find::Prev),
        KeyCode::Down | KeyCode::Right => editor.find(query, Find::Next),
        _ => editor.find(query, Find::FromStart),
    })?;
    editor.clear_matches();
    if query.is_none() {
        editor.restore_view(saved);
    }
    Ok(())
}

把原来的 prompt 泛化：prompt 只是「空回调」的特例，真正干活的是 prompt_with——它每按一键都回调一次：

/// Reads a line from the message bar. `Esc` cancels, `Enter` confirms.
fn prompt(editor: &mut Editor, label: &str) -> io::Result<Option<String>> {
    prompt_with(editor, label, |_, _, _| {})
}

/// Like [`prompt`], but calls `on_key` after every key press (used by live search).
fn prompt_with(
    editor: &mut Editor,
    label: &str,
    mut on_key: impl FnMut(&mut Editor, &str, KeyCode),
) -> io::Result<Option<String>> {
    let mut input = String::new();
    loop {
        editor.set_message(format!("{label}{input}"));
        render(editor)?;

        let Event::Key(key) = event::read()? else {
            continue;
        };
        if !key.is_press() {
            continue;
        }

        match key.code {
            KeyCode::Esc => {
                on_key(editor, &input, KeyCode::Esc);
                editor.clear_message();
                return Ok(None);
            }
            KeyCode::Enter => {
                if !input.is_empty() {
                    on_key(editor, &input, KeyCode::Enter);
                    editor.clear_message();
                    return Ok(Some(input));
                }
            }
            KeyCode::Backspace => {
                input.pop();
            }
            KeyCode::Char(ch) if !key.modifiers.contains(KeyModifiers::CONTROL) => input.push(ch),
            _ => {}
        }
        on_key(editor, &input, key.code);
    }
}

逐段拆解

  • 为什么 Row 返回「分段」而不是一个字符串？ 「哪一段命中」只有 Row 说得清（它持有字符和命中区间）；「命中长什么样」属于渲染层。 把这两件事分开，Row 里就不会出现终端转义码，ui 也不必懂字符坐标。
  • push_segment 合并同类段：相邻且 matched 相同的文本并成一段， 减少无谓的 SetAttribute，也让「边界」在测试里一眼看清（hello 普通 / world 命中）。
  • is_some_and：Option 上的「有值且满足谓词」，比 map_or(false, …) 或手写 match 更直达意图。
  • prompt / prompt_with：前者是后者的空回调特例。 查找传入的回调每按一键都调用，于是「输入」与「重找」同步发生——这就是实时搜索。
  • 环绕靠取模：Next 从 last_match + 1 起、Prev 从 last_match - 1 起，用 % count 回绕；查到就记下新的 last_match。 FromStart 一律从第 0 行起（查询变了，重新找首个匹配）。
  • Esc 还原靠快照：查找前 view_state() 拍下 cx/cy/coloff/rowoff；取消时 restore_view() 放回。 Enter 不还原——因为你就是想停在命中处。
  • 命中按「字符下标」而非「显示列」：cx 本就是字符下标， 高亮也按字符区间记；显示列只在渲染那一刻换算（tab 展开、宽字符占两列）。

小测

1. render_window 为什么返回 Vec<Segment>，而不是一个带 ANSI 的字符串？

  • 让 Row 只描述「哪段命中」，样式由 ui 决定
  • 因为 String 里不能存放反显控制码
  • 因为分段比字符串更省内存
  • 为了支持同时高亮多行
看答案

第一个。分层：Row 决定命中区间，ui 决定用反显还是别的样式。 这样 Row 与终端无关，可单独测试。

2. Esc 要能还原，需要在查找前保存哪些状态？

  • 光标 cx/cy 与视口 coloff/rowoff 四处
  • 只保存当前文件名
  • 整份文档内容
  • 只需要查询字符串
看答案

第一个。查找会同时改动光标和滚动位置，所以两样都要拍快照；文档内容没被改动， 查询本身也无需保存。

3. 「到末尾环绕到开头」靠什么实现？

  • 对行数取模，从 last_match 前后推进
  • 先复制一份文档再从头搜
  • 用递归把每一行都试一遍
  • 依靠终端自身的滚动能力
看答案

第一个。(start + offset) % count（向前）与 (start + count - offset) % count（向后）天然回绕，最多扫描 count 行。
