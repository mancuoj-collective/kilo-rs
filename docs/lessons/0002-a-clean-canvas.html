第 1 课的程序只会往终端里打印，退出后那些字还赖在屏幕上。这一课我们给它一整块 独立的画布，学会一帧一帧地画屏幕，并且补上第 1 课留下的那个洞—— 让 panic 也能把终端还给你。

本课成果

  • cargo run：程序占满整屏，空行显示 ~，约 1/3 处显示欢迎语；
  • 拖动改变窗口大小，画面会自动重画适应新尺寸；
  • Ctrl+Q 退出后，你原来 shell 的内容原样回来（不是被一堆 ~ 覆盖）；
  • 即使 panic，报告也是干净排版的，终端毫发无损。

要补的两个洞

第 1 课结束时，程序能接管终端、响应按键了，但有两个问题：

  1. 太吵：程序把内容直接打在当前屏幕上，退出后这些内容留在那里，污染了你的 shell。
  2. panic 报告很难看：报告在 Drop 之前打印，那时还在 raw mode，\n 不回车，于是一路向右缩进成楼梯。

洞 1：备用屏幕（alternate screen）

终端其实有两块屏幕：正常屏幕（你和 shell 一直用的）和备用屏幕。 终端里的 vim、less 都用备用屏幕工作。进入时切过去，退出时切回来—— 正常屏幕上的内容原封不动地恢复。这正是我们要的效果。

crossterm 提供了两个对应的命令：EnterAlternateScreen / LeaveAlternateScreen。 顺便用 cursor::Hide / cursor::Show 把光标藏起来（否则它会在画面上乱闪）。

设计 「进备用屏幕」「开 raw mode」「藏光标」这三件事必须成组出现、成组撤销， 所以它们理应由第 1 课那个守卫的升级版来管——我们把它从 RawModeGuard 改名成 Terminal，它现在持有的是「全屏编辑状态」。

洞 2：panic hook

Rust 允许你安装一个 panic hook：它在 panic 发生之后、栈开始展开之前被调用。 我们在这里先把终端恢复原状，再把信息交回给原来的 hook（color-eyre 设置的那个） 去打印报告。这样报告就会打在正常屏幕上、用正常的换行输出。

fn install_panic_hook() {
    let hook = std::panic::take_hook();      // the current hook (color-eyre's)
    std::panic::set_hook(Box::new(move |info| {
        restore();                            // restore the terminal first
        hook(info);                           // then let color-eyre print the report
    }));
}

顺序 必须在 color_eyre::install() 之后装这个 hook， 才能「包住」它设置的 hook。装反了，color-eyre 会把我们的 hook 覆盖掉，报告又变乱。

看不太懂 Box 和 move？展开这里

move：闭包默认借用它用到的外部变量。但这个闭包要存进全局、 活得比函数长，借用会变成悬垂引用（编译器会报 E0597）； move 让它把 hook 移动进自己内部，于是闭包拥有它、可以 'static。 核心问题还是那句：这份数据该被谁拥有、活多久？

Box：闭包的具体类型是编译器生成的匿名类型，写不出来。 set_hook 要在全局存「任意一个函数」，所以用 trait object dyn Fn(…) 把具体类型擦掉。而 dyn 的大小编译期未知（E0277），不能按值传递， 必须放在指针后面——Box<dyn Fn(…)> 就是「堆上、独占、能自动释放」的那个指针。

需要掌握到什么程度：move 与 Box 是必须理解的基础 （线程、错误对象、递归类型都会用到）；但这段 panic hook 的具体写法可以当模板，读懂即可，不必默写。

把一帧「攒」出来：queue! 与 execute!

每次往 stdout 写东西都是一次系统调用，很贵。画一帧要发很多命令（清屏、移动光标、打印……）， 所以 crossterm 提供了两种执行方式：

宏行为用在哪
execute!立即执行并 flush一次性的开关，如进入/退出备用屏幕
queue!排队，等你手动 flush() 才一次性写出画帧：攒一整帧，最后 stdout.flush()

这就是 C 版 kilo 里那个 abuf（追加缓冲区）在现代 crossterm 里的对应物—— 只不过我们不用手写 realloc 了。

动手

任务 把 src/main.rs 改成下面的样子

先通读一遍，理解每一块在做什么，再亲手敲进去：

use std::io::{self, Write};

use color_eyre::Result;
use crossterm::{
    cursor::{self, MoveTo},
    event::{self, Event, KeyCode, KeyModifiers},
    execute, queue,
    style::Print,
    terminal::{self, Clear, ClearType, EnterAlternateScreen, LeaveAlternateScreen},
};

const VERSION: &str = env!("CARGO_PKG_VERSION");

/// Holds full-screen editing state: raw mode, the alternate screen, a hidden cursor.
/// Restores the terminal when dropped.
struct Terminal;

impl Terminal {
    fn enter() -> io::Result<Self> {
        terminal::enable_raw_mode()?;

        // Build the guard *before* the fallible command: if `execute!` fails,
        // `guard` is dropped on the early return and raw mode is still restored.
        let guard = Self;
        let mut stdout = io::stdout();
        execute!(stdout, EnterAlternateScreen, cursor::Hide)?;

        Ok(guard)
    }
}

impl Drop for Terminal {
    fn drop(&mut self) {
        restore();
    }
}

/// Restores the terminal. Shared by `Drop` and the panic hook.
fn restore() {
    let mut stdout = io::stdout();
    let _ = execute!(stdout, cursor::Show, LeaveAlternateScreen);
    let _ = terminal::disable_raw_mode();
}

/// Installs a panic hook that restores the terminal, then hands off to the
/// previous hook.
///
/// Must be called *after* `color_eyre::install()`, to wrap the hook it sets.
fn install_panic_hook() {
    let hook = std::panic::take_hook();
    std::panic::set_hook(Box::new(move |info| {
        restore();
        hook(info);
    }));
}

fn main() -> Result<()> {
    color_eyre::install()?;
    install_panic_hook();

    let _terminal = Terminal::enter()?;
    draw()?;

    loop {
        match event::read()? {
            Event::Key(key) if key.is_press() => match key.code {
                KeyCode::Char('q') if key.modifiers.contains(KeyModifiers::CONTROL) => break,
                _ => {}
            },
            Event::Resize(_, _) => draw()?,
            _ => {}
        }
    }

    Ok(())
}

/// Draws one frame: clear the screen, fill empty rows with `~`, and show the
/// welcome line about a third of the way down.
fn draw() -> io::Result<()> {
    let (cols, rows) = terminal::size()?;
    let mut stdout = io::stdout();

    queue!(stdout, Clear(ClearType::All), MoveTo(0, 0))?;

    for y in 0..rows {
        if y == rows / 3 {
            queue!(stdout, Print(welcome_line(cols)))?;
        } else {
            queue!(stdout, Print('~'))?;
        }

        // No newline after the last row, or the whole screen scrolls up.
        if y + 1 < rows {
            queue!(stdout, Print("\r\n"))?;
        }
    }

    queue!(stdout, MoveTo(0, 0))?;
    stdout.flush()
}

fn welcome_line(cols: u16) -> String {
    let text = format!("~ Kilo editor -- version {VERSION}");
    text.chars().take(cols as usize).collect()
}

逐段拆解（只看这一课的新东西）

  • const VERSION: &str = env!("CARGO_PKG_VERSION");：env! 在 编译期读取，把 Cargo.toml 里的 version 直接编进二进制。 不用像 C 版那样手写 "0.0.1"，也不会忘记同步。
  • 为什么 let guard = Self; 必须出现在 execute!(…)? 之前？ 因为 execute! 可能失败，一旦失败就提前返回。如果那时还没有守卫， 就没人负责关掉已经打开的 raw mode——终端会坏。先造守卫，再做可能失败的事， 失败时守卫会自动析构并清理。这是上一课那条规则的延续。
  • 结尾必须是 Ok(guard)，不能是 Ok(Self)。 Ok(Self) 会新造一个 Terminal 返回，而把 guard 留在函数里—— 它会在函数退出时立刻析构，等于 raw mode 刚开就被关掉。编译器会报 unused variable: guard，这不是噪声，而是在提醒你守卫被丢弃了。
  • restore() 被 Drop 和 panic hook 共用：恢复逻辑只有一份， 不会出现「Drop 里改了、hook 里忘了改」的分裂。
  • queue! 攒命令、最后 stdout.flush() 一次性写出。注意 draw 里 queue! 用 ? 提前返回时不需要手动恢复终端——守卫兜底。
  • 最后一行后面不写 \r\n：如果在屏幕最后一行换行，终端会把整屏向上滚动， 画面就错位了。所以用 if y + 1 < rows 明确表达「不是最后一行才换行」—— 比 if y > 0（把换行放在下一行的开头）更贴合直觉。
  • text.chars().take(cols as usize).collect()：把文字截断到终端宽度。 读法是把三个迭代器适配器连起来：.chars() 产出 char → .take(n) 最多取 n 个 → .collect() 收成一个 String （目标类型由函数返回类型 -> String 推导）。
  • 为什么不用 &text[..cols]？那是按字节切，cols 一旦落在多字节字符中间就会 panic；.chars() 数的是字符，永不 panic。 但字符数 ≠ 终端列宽（中文占 2 列），要彻底做对得等以后引入 unicode-width。
  • Event::Resize(_, _) => draw()?：终端尺寸变化会发来 Resize 事件， 重画一帧即可。窗口大小用 terminal::size()，返回 (columns, rows)。

挑战 验证 panic hook 真的有用

在 let _terminal = Terminal::enter()?; 后面临时加一行 panic!("boom");， cargo run。对比第 1 课的现象：这次 color-eyre 的报告应该排版正常， 而且终端完全没有坏。原因就是 hook 先跑了 restore()。做完删掉这行。

加了 panic!("boom") 却看不到 panic 信息？

信息其实打印了，但打在了备用屏幕上，随后被「离开备用屏幕」一起抹掉了。 这说明恢复发生在打印之后——我们的 hook 没有先执行，真正跑的是别的 hook（color-eyre 自己的或默认的）。

按顺序检查：

  1. install_panic_hook(); 真的在 main 里被调用了吗？（定义 ≠ 调用）
  2. 它在 color_eyre::install()?; 之后吗？（否则会被覆盖）
  3. 它在 Terminal::enter()? 和 panic! 之前吗？（否则来不及）

验证：在 hook 第一行加 eprintln!("[hook] restore");。看不到它，就说明这个 hook 没被安装。

小测

1. EnterAlternateScreen 的作用是什么？

  • 开一块独立画布，退出后恢复原来的屏幕内容
  • 清空当前屏幕，且原来的内容无法再恢复
  • 隐藏输入光标并冻结键盘输入事件
  • 切换终端到夜间配色以保护视力
看答案

第一个。备用屏幕是终端提供的第二块缓冲区，vim / less 都这么用。 离开时正常屏幕的内容原样回来——所以它比单纯「清屏」更好。

2. 画一帧时为什么用 queue! 而不是 execute!？

  • queue! 攒到 flush 一次性写，减少系统调用
  • execute! 不支持一次执行多个命令
  • queue! 会自动帮程序接管 Ctrl 组合键
  • execute! 会清空屏幕缓冲导致闪烁
看答案

第一个。execute! 每条命令都立即 flush；queue! 只是把字节写进缓冲， 由最后那次 stdout.flush() 统一提交。帧越大，差距越明显。

3. 为什么 draw 里最后一行后面不写 \r\n？

  • 在屏幕底行换行会把整屏向上滚动，导致错位
  • 否则光标位置会因为制表符而计算错误
  • 否则终端不会把缓冲区的命令真正刷出去
  • raw mode 下不允许连续两次换行操作
看答案

第一个。所以换行只加在「行与行之间」——用 if y + 1 < rows 明确表达 「不是最后一行才换行」，而不是每行都追加。 这也是为什么原版 kilo 会预留两行给状态栏——底行绝不能多写一个换行。
