第 11 课 · 语法高亮

kilo-rs 课程 · Lesson 0011 · 预计 60–75 分钟 · 新模块：syntax.rs（规则表 + 状态机）

到目前为止，正文只有一种颜色（命中时才反显）。这一课给 C 与 Rust 文件上色： 注释、字符串、数字、关键字各归其位。做法是经典的两件事——一张规则表（数据） 加一个小词法分析器（行为）。难点是 /* … */ 会跨行， 这正是一个「状态机」要解决的问题。

本课成果

  • 打开 .c / .rs 文件：// 与 /* */ 注释、 "…" 字符串（含转义）、数字、关键字分别上色；
  • 状态栏右侧出现 filetype | row/total（例如 c | 1/5、rs | 1/5）；
  • 编辑时高亮实时更新，跨行注释状态正确传播；
  • 新模块 src/syntax.rs——规则是数据，词法是行为，渲染仍归 ui。

思路：数据 + 行为 + 分层

关注点归属
「哪种语言的规则」（扩展名、关键字、注释标记）syntax::Syntax（纯数据表）
「一行里每个字符属于哪类」Syntax::highlight（状态机）
「这一类长什么样（颜色）」ui（渲染唯一负责样式的层）

syntax.rs 里不出现任何终端颜色：它只产出「类别」， 由 ui 把类别映射成颜色。这样词法可以单独写测试，换主题也不必动规则。

impl Syntax {
    /// Picks the rules for `path`, by extension or substring match.
    #[must_use]
    pub fn for_path(path: &str) -> Option<&'static Syntax> {
        let extension = path.rsplit_once('.').map(|(_, extension)| extension);
        HLDB.iter().find(|syntax| syntax.matches(path, extension))
    }

    fn matches(&self, path: &str, extension: Option<&str>) -> bool {
        self.filematch
            .iter()
            .any(|pattern| match pattern.strip_prefix('.') {
                Some(pattern) => extension == Some(pattern),
                None => path.contains(pattern),
            })
    }

核心：一个字符一个字符地扫，维护 prev_sep（上一个是不是分隔符）、 in_string 与 in_comment 两个状态，返回「类别数组 + 本行是否还在注释里」。 这是 editorUpdateSyntax 的直译：

    /// Categorises `chars`, returning the categories (aligned with `chars`) and whether
    /// the row ends inside a multi-line comment — i.e. whether the next row starts in one.
    #[must_use]
    pub fn highlight(&self, chars: &[char], begins_in_comment: bool) -> (Vec<Highlight>, bool) {
        let mut hl = vec![Highlight::Normal; chars.len()];
        let mut prev_sep = true;
        let mut in_string: Option<char> = None;
        let mut in_comment = begins_in_comment;
        let mut i = 0;

        while i < chars.len() {
            let c = chars[i];
            let prev_hl = if i > 0 { hl[i - 1] } else { Highlight::Normal };

            // A single-line comment swallows the rest of the row.
            let singleline = self.singleline_comment_start;
            if in_string.is_none()
                && !in_comment
                && singleline.is_some_and(|start| starts_with(chars, i, start))
            {
                hl[i..].fill(Highlight::Comment);
                break;
            }

            if in_string.is_none() {
                if in_comment {
                    if let Some(end) = self.multiline_comment_end {
                        if starts_with(chars, i, end) {
                            hl[i..i + end.chars().count()].fill(Highlight::MultilineComment);
                            i += end.chars().count();
                            in_comment = false;
                            prev_sep = true;
                            continue;
                        }
                    }
                    hl[i] = Highlight::MultilineComment;
                    i += 1;
                    continue;
                }
                if let Some(start) = self.multiline_comment_start {
                    if starts_with(chars, i, start) {
                        hl[i..i + start.chars().count()].fill(Highlight::MultilineComment);
                        i += start.chars().count();
                        in_comment = true;
                        continue;
                    }
                }
            }

            if !self.string_delimiters.is_empty() {
                if let Some(quote) = in_string {
                    hl[i] = Highlight::String;
                    if c == '\\' && i + 1 < chars.len() {
                        hl[i + 1] = Highlight::String;
                        i += 2;
                        continue;
                    }
                    if c == quote {
                        in_string = None;
                    }
                    i += 1;
                    prev_sep = true;
                    continue;
                } else if self.string_delimiters.contains(&c) {
                    in_string = Some(c);
                    hl[i] = Highlight::String;
                    i += 1;
                    continue;
                }
            }

            if self.highlight_numbers
                && ((c.is_ascii_digit() && (prev_sep || prev_hl == Highlight::Number))
                    || (c == '.' && prev_hl == Highlight::Number))
            {
                hl[i] = Highlight::Number;
                i += 1;
                prev_sep = false;
                continue;
            }

            if prev_sep {
                if let Some((len, second)) = self.match_keyword(chars, i) {
                    let kind = if second {
                        Highlight::Keyword2
                    } else {
                        Highlight::Keyword1
                    };
                    hl[i..i + len].fill(kind);
                    i += len;
                    prev_sep = false;
                    continue;
                }
            }

            prev_sep = is_separator(c);
            i += 1;
        }

        (hl, in_comment)
    }

三个小工具（关键字匹配、前缀判断、分隔符集合）：

    /// Length of a keyword starting at `at`, and whether it is a "type" keyword.
    fn match_keyword(&self, chars: &[char], at: usize) -> Option<(usize, bool)> {
        self.keywords.iter().find_map(|keyword| {
            let second = keyword.ends_with('|');
            let name = keyword.trim_end_matches('|');
            let len = name.chars().count();
            let boundary = chars.get(at + len).is_none_or(|&c| is_separator(c));
            (boundary && starts_with(chars, at, name)).then_some((len, second))
        })
    }
}

/// Whether `pattern` occurs in `chars` starting at `at`.
fn starts_with(chars: &[char], at: usize, pattern: &str) -> bool {
    pattern
        .chars()
        .enumerate()
        .all(|(offset, expected)| chars.get(at + offset) == Some(&expected))
}

/// Whether `c` ends a word (kilo's separator set).
fn is_separator(c: char) -> bool {
    c.is_whitespace() || ",.()+-/*=~%<>[];".contains(c)
}

    fn keywords_numbers_and_comments() {
        let syntax = Syntax::for_path("x.c").unwrap();
        let text = "return 42; // note";
        let (hl, _) = syntax.highlight(&chars(text), false);

        assert_eq!(hl[0], Highlight::Keyword1); // return

        assert_eq!(hl[comment], Highlight::Comment);

    fn multiline_comments_carry_across_rows() {
        let syntax = Syntax::for_path("x.c").unwrap();

        let (_, ends) = syntax.highlight(&chars("/* open"), false);
        assert!(ends);

        let (hl, ends) = syntax.highlight(&chars("still */ int x;"), true);
        assert!(!ends);
        assert_eq!(hl[0], Highlight::MultilineComment);
        assert_eq!(hl[9], Highlight::Keyword2); // int, after the comment closes

        let syntax = Syntax::for_path("main.rs").unwrap();

        assert_eq!(hl[0], Highlight::Keyword1); // let

/// Appends `text` to `segments`, merging it into the previous run when both style keys agree.
fn push_segment(segments: &mut Vec<Segment>, text: &str, highlight: Highlight, matched: bool) {
    if text.is_empty() {
        return;
    }
    match segments.last_mut() {
        Some(last) if last.highlight == highlight && last.matched == matched => {
            last.text.push_str(text);
        }
        _ => segments.push(Segment {
            text: text.to_owned(),
            highlight,
            matched,
        }),
    }
}

    /// Highlights all rows from scratch. Call this after the syntax changes.
    fn highlight_all(&mut self) {
        let Some(syntax) = self.syntax else {
            return;
        };
        let mut open_comment = false;
        for row in &mut self.rows {
            let (hl, ends) = syntax.highlight(row.chars(), open_comment);
            row.set_highlight(hl);
            row.set_open_comment(ends);
            open_comment = ends;
        }
    }

    /// Re-highlights from row `from`, continuing only while the open-comment state changes
    /// (the same short-circuit kilo uses).
    fn refresh_syntax(&mut self, from: usize) {
        let Some(syntax) = self.syntax else {
            return;
        };
        let mut open_comment = from > 0 && self.rows[from - 1].open_comment();
        for row in &mut self.rows[from..] {
            let (hl, ends) = syntax.highlight(row.chars(), open_comment);
            let changed = row.open_comment() != ends;
            row.set_highlight(hl);
            row.set_open_comment(ends);
            if !changed {
                break;
            }
            open_comment = ends;
        }
    }

    /// Picks a syntax from the file name and (re-)highlights the whole document.
    fn select_syntax(&mut self) {
        self.syntax = self.filename.as_deref().and_then(Syntax::for_path);
        self.highlight_all();
    }

任务 4 改 src/ui.rs：类别 → 颜色

逐段打印时按类别上色、命中则叠反显。颜色映射放在 ui（渲染唯一负责样式的地方）， 用的正是 kilo 的 ANSI 槽位：

/// Writes one rendered segment with its syntax color and/or match overlay.
fn draw_segment(stdout: &mut io::Stdout, segment: &Segment) -> io::Result<()> {
    let color = highlight_color(segment.highlight);
    if let Some(color) = color {
        queue!(stdout, SetForegroundColor(color))?;
    }
    if segment.matched {
        queue!(stdout, SetAttribute(Attribute::Reverse))?;
    }
    queue!(stdout, Print(&segment.text))?;
    if segment.matched {
        queue!(stdout, SetAttribute(Attribute::Reset))?;
    }
    if color.is_some() {
        queue!(stdout, SetForegroundColor(Color::Reset))?;
    }
    Ok(())
}

/// The terminal color for a syntax category (`None` = the default foreground).
///
/// These are the standard ANSI slots kilo uses (`editorSyntaxToColor`): cyan comments,
/// yellow keywords, green type keywords, magenta strings, red numbers.
fn highlight_color(highlight: Highlight) -> Option<Color> {
    Some(match highlight {
        Highlight::Normal => return None,
        Highlight::Comment | Highlight::MultilineComment => Color::DarkCyan,
        Highlight::Keyword1 => Color::DarkYellow,
        Highlight::Keyword2 => Color::DarkGreen,
        Highlight::String => Color::DarkMagenta,
        Highlight::Number => Color::DarkRed,
    })
}

试一个跨行注释：写 /* 后回车继续打字，整段（含空行）都应是注释色。

逐段拆解

  • 规则与词法分离：Syntax 是纯数据；加一门语言只加一条 HLDB 表项， 不用碰 highlight。这就是「数据驱动」。
  • 状态机：扫描时只记三个状态——prev_sep、in_string、 in_comment。关键字/数字只在 prev_sep 为真时开始，避免把 intfoo 里的 int 也点亮。
  • 跨行注释靠「返回值」传递：highlight 返回「本行结束时是否仍在注释中」， 下一行把这当作 begins_in_comment。行与行之间只通过这一个布尔耦合。
  • 增量更新：编辑某行只重算它；只有当它的「注释开闭状态」发生变化时才继续重算下一行—— 因为再往下的行只依赖这个布尔，不变就不必动。这是 kilo 的短路策略。
  • hl 与 chars 等长：一个必须被维护的不变式。 所以每个改字符的方法都顺手改 hl；render_window 仍用 hl.get(index) 防御性取值，万一错位也不会 panic。
  • 样式归 ui：syntax 只给类别，颜色映射在 ui。 DarkCyan 等对应 kilo 的 ANSI 31–36 槽位。

1. 把「规则」做成数据表、把「词法」写成函数，最大的好处是？

  • 加一门语言只需新增一条表项，不必改词法代码
  • 可以让程序启动更快
  • 可以少写单元测试
  • 可以让颜色自动适配终端主题
看答案

第一个。数据与行为分离后，语言规则是「填表」，词法是稳定的引擎。加上「样式归 ui」， 三者各司其职。

2. 为什么 highlight 要把「本行是否仍在注释里」返回出去？

  • 因为多行注释可以跨行，下一行需要知道从哪种状态开始
  • 因为 Vec<Highlight> 装不下这个信息
  • 因为它要和搜索命中做区分
  • 因为返回值比输出参数更快
看答案

第一个。行是有界的处理单位，而 /* … */ 可以跨行；把这个布尔状态一行行传下去， 就能正确高亮整段注释。

3. 编辑一行后，refresh_syntax 什么时候可以停下？

  • 当这一行的「注释开闭状态」没有变化时
  • 处理完当前行就必须停
  • 一直到文档最后一行都不能停
  • 当遇到空行时停下
看答案

第一个。后续行的高亮只依赖「上一行是否在注释里」这一个布尔；它没变，后面就都不受影响， 可以立即停。

主要资料

  • 对应章节：snaptoken 第 7 章 （editorUpdateSyntax / HLDB / editorSyntaxToColor）。
  • 数据与行为分离、把行为作为参数：m04-zero-cost。
  • 速查：现代 Rust 惯用法 （Option::is_some_and、then_some）。

收尾 到这里，kilo 的核心——打开 / 显示 / 移动 / 编辑 / 保存 / 查找—— 再加上语法高亮就完整了。与原版 kilo.c 还有一些细节差距 （PageUp/PageDown、Tab 插入、控制字符的显示、若干提示文案）， 留待一次整体回顾时再决定取舍。
