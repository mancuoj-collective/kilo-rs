三个小知识

① 命令行参数：env::args()

std::env::args() 返回一个迭代器，第 0 项是程序名，第 1 项就是你传的文件名。 用 .nth(1) 拿到它（Option<String>）：

let path = std::env::args().nth(1);   // Some("README.md") or None

注意 用 cargo run 传参必须加 --： cargo run -- README.md。-- 之前是给 cargo 的，之后才是给程序的。

② 读文件：一行一个 String

最直接的读法是 fs::read_to_string，一次读成整块 String， 再用 .lines() 切开。lines() 会处理 \n 和 \r\n，并去掉行尾的换行符。

关键 .lines() 产出的是 &str，借用自那块文件内容。 所以要用 .map(str::to_owned) 把每一行变成独立拥有的 String—— 否则一旦文件内容那块内存被释放，这些行就成了悬垂借用。这一步正是所有权在起作用。

③ 渲染：有内容就画，没有就画 ~

渲染函数现在接收一个 &[String]：前几行是文件内容，超出文件行数的部分用 ~ 补满； 文件如果为空，就显示欢迎语。

现代写法 参数写成 &[String] 而不是 &Vec<String>。 切片是更通用的类型：Vec、数组以及切片本身都能自动传入。函数尽量收窄到它真正需要的能力。 （Apollo《Rust Best Practices》§1.1）

动手

任务 把 src/main.rs 改成下面的样子

前两课的部分没变，重点看 main、draw、truncate：

use std::{
    env,
    fs,
    io::{self, Write},
};

use color_eyre::Result;
use crossterm::{
    cursor::{self, MoveTo},
    event::{self, Event, KeyCode, KeyModifiers},
    execute, queue,
    style::Print,
    terminal::{self, Clear, ClearType, EnterAlternateScreen, LeaveAlternateScreen},
};

const NAME: &str = env!("CARGO_PKG_NAME");
const VERSION: &str = env!("CARGO_PKG_VERSION");

/// Holds full-screen editing state: raw mode, the alternate screen, a hidden cursor.
struct Terminal;

impl Terminal {
    fn enter() -> io::Result<Self> {
        terminal::enable_raw_mode()?;

        // Build the guard before the fallible command.
        let guard = Self;
        let mut stdout = io::stdout();
        execute!(stdout, EnterAlternateScreen, cursor::Hide)?;

        Ok(guard)
    }
}

impl Drop for Terminal {
    fn drop(&mut self) {
        restore();
    }
}

fn restore() {
    let mut stdout = io::stdout();
    let _ = execute!(stdout, cursor::Show, LeaveAlternateScreen);
    let _ = terminal::disable_raw_mode();
}

fn install_panic_hook() {
    let hook = std::panic::take_hook();
    std::panic::set_hook(Box::new(move |info| {
        restore();
        hook(info);
    }));
}

fn main() -> Result<()> {
    color_eyre::install()?;
    install_panic_hook();

    // Read the file name from argv; with no argument, start with an empty buffer.
    let lines = match env::args().nth(1) {
        Some(path) => fs::read_to_string(&path)?
            .lines()
            .map(str::to_owned)
            .collect(),
        None => Vec::new(),
    };

    let _guard = Terminal::enter()?;
    draw(&lines)?;

    loop {
        match event::read()? {
            Event::Key(key) if key.is_press() => match key.code {
                KeyCode::Char('q') if key.modifiers.contains(KeyModifiers::CONTROL) => break,
                _ => {}
            },
            Event::Resize(_, _) => draw(&lines)?,
            _ => {}
        }
    }

    Ok(())
}

/// Draws one frame: the first lines of the file, padded with `~`; the welcome
/// line for an empty file.
fn draw(lines: &[String]) -> io::Result<()> {
    let (cols, rows) = terminal::size()?;
    let mut stdout = io::stdout();

    queue!(stdout, Clear(ClearType::All), MoveTo(0, 0))?;

    for y in 0..rows {
        if let Some(line) = lines.get(y as usize) {
            queue!(stdout, Print(truncate(line, cols)))?;
        } else if lines.is_empty() && y == rows / 3 {
            queue!(stdout, Print(welcome_line(cols)))?;
        } else {
            queue!(stdout, Print('~'))?;
        }

        if y + 1 < rows {
            queue!(stdout, Print("\r\n"))?;
        }
    }

    queue!(stdout, MoveTo(0, 0))?;
    stdout.flush()
}

/// Truncates text to the terminal width (by chars, not bytes).
fn truncate(text: &str, width: u16) -> String {
    text.chars().take(width as usize).collect()
}

fn welcome_line(cols: u16) -> String {
    let text = format!("~ {NAME} editor -- version {VERSION}");
    truncate(&text, cols)
}

逐段拆解

  • 读文件放在 Terminal::enter() 之前：这是有意为之。文件打开失败时， ? 会让 main 提前返回，此时还没进备用屏幕， color-eyre 的报错能干干净净地打印在正常屏幕上。凡是「可能失败的准备工作」， 都安排在接管屏幕之前。
  • fs::read_to_string(&path)?：一次读成整块 String。它要求文件是合法 UTF-8—— 二进制文件会报错，这是本课的一个已知限制。
  • .lines().map(str::to_owned).collect()：切行、把每行 &str 转成拥有的 String、收进 Vec。目标类型由后面 draw(&lines) 的签名推导出来。
  • match … { Some(path) => …, None => Vec::new() }：有文件名就读，没有就构造一个空 Vec。 空 Vec 会让 draw 走欢迎语分支。
  • lines.get(y as usize)：Vec 的 .get 返回 Option<&String>， 正好表达「这一行可能不存在」。不存在就走补 ~ 的分支。y as usize 是 u16 → usize 的安全加宽转换。
  • truncate()：从上一课的欢迎语里抽出来的。它现在被两处用到 （欢迎语、每一行文件内容），而且名字表意清楚，所以值得独立成函数。
  • draw(&lines)：只借用 lines，不拿走所有权。 Resize 分支可以反复重画，正是因为 lines 还归 main 所有。

  2. 故意弄出一个很长的行（比如把窗口拖窄），观察行是被截断，而不是换行或错位。
  3. 不带参数 → 欢迎语。
  4. 文件名写错 → 干净的错误报告（还在正常屏幕上）。

已知限制（先记着，之后处理）

  • 只能显示前 rows 行：还不能滚动。下一步就做光标和滚动。
  • 必须是合法 UTF-8：read_to_string 对二进制文件会报错。 原版 C kilo 是字节导向的，这里是一个真实的取舍——等真正需要支持二进制文件时再处理。
  • 宽字符没处理：超长行按「字符数」截断，但中文占 2 列，还不精确。

小测

1. .lines() 产出的每一行是什么类型？

  • &str，借用自文件内容
  • String，每一行独立拥有
  • Vec<u8>，原始字节序列
  • char，一次一个字符
看答案

第一个。正因为是借用，我们才需要 .map(str::to_owned) 把它们变成拥有所有权的 String——否则那块文件内容一旦释放，这些行就悬垂了。

2. 为什么读文件要放在 Terminal::enter() 之前？

  • 出错时报告能干净地打在正常屏幕上
  • 否则文件内容会被备用屏幕吞掉
  • 因为 raw mode 下无法读取文件
  • 为了让程序编译得更快一些
看答案

第一个。失败发生在接管屏幕之前，? 提前返回时终端还是正常状态，报错清晰可读。 把「可能失败的准备工作」放在侵入性操作之前，是终端程序的通用原则。

3. draw 的参数为什么写成 &[String] 而不是 &Vec<String>？

  • 切片更通用，数组、Vec 都能传进来
  • 因为 Vec 不能被不可变借用
  • 因为切片会自动复制一份数据
  • 因为 &Vec 会移动走所有权
看答案

第一个。切片 &[T] 是更宽泛的「一段连续数据」；&Vec<T> 会自动解引用成 &[T]，所以收 &[T] 的接口能接受更多输入，也更少绑定实现细节。 这是「函数参数尽量收窄」的典型例子。
